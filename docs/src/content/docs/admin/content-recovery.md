McWeb 没有一个可以恢复所有数据的通用回收站。先确认删除的是哪类内容，再选择正确入口。

| 内容 | 管理入口 | 恢复结果 |
| --- | --- | --- |
| 官网页面、文章 | “官网 → 回收站”，`/admin/website/recycle-bin` | 恢复为草稿，需要重新检查和发布 |
| 社区主题、回复、私信、帖子附件、资料留言与留言回复 | “系统 → 数据治理”，`/admin/system/data-governance` | 在策略允许时恢复原内容，并保留生命周期记录 |
| Minecraft 世界 | 服务器详情的“托管世界备份与恢复” | 按恢复计划处理世界目录，不属于内容回收站 |

普通工作人员权限不会自动授予管理后台的数据治理能力。应由具备对应后台模块和专用权限的人员操作。

## 官网：归档、回收站与永久清理

“归档”用于停止发布并保留日后编辑的内容。“移入回收站”用于删除当前内容的公开可见性，同时留下恢复记录；这一步不是立即永久删除。

误删时：

1. 在“官网 → 回收站”找到页面或文章，核对标题、路径、删除时间、操作者和原因。
2. 打开详情，查看恢复阻断项及需要时的修订历史。
3. 填写恢复原因，按提示输入当前内容标题，选择“恢复为草稿”。
4. 在编辑页重新核对内容、区块、语言、主题和导航，再由有发布权限的人员发布。

恢复需要 `website.content.restore` 及对应页面或文章的读取、编辑权限。路径被占用、首页冲突、主题缺失、区块类型失效或导航冲突会阻止恢复；先处理明确的问题，不能强行覆盖现有内容。

需要回到某个历史版本时，使用该内容的“修订”入口。修订恢复会更新当前内容并设为草稿，不会另建一份已发布副本。

### 永久清理官网内容

只有具备 `website.content.purge` 和对应读取权限的人员才能操作。保留期未满、存在有效保全、可见导航引用、定时发布状态或缺少必要修订记录时，系统会拒绝清理。

满足条件后，仍需在危险操作确认中核对预览、填写原因、重新验证身份并输入页面要求的确认文字。永久清理不能再从回收站或修订历史恢复；不要把“最早清理时间已到”当作必须删除的命令。

## 社区：数据治理

“系统 → 数据治理”分为“内容生命周期”“保留保全”和“保留矩阵”。查看需要 `data_governance.read`；软删除、恢复、永久清理、策略管理和保全管理分别需要独立权限。

### 软删除与恢复

在“内容生命周期”核对资源类型、目标标识、状态、软删除时间、最早清理时间和阻断项。使用“软删除内容”时选择受支持的资源类型，填写数字 ID 或公开 ID 和原因，避免误操作同名内容。

软删除会使内容不可见，但不代表数据已经被永久清除。恢复时打开对应生命周期记录，确认原记录仍存在且当前策略允许恢复，填写可审计原因后提交。页面会保留原删除和恢复历史。

已经永久清理的内容无法恢复；通过关闭账户的“申请删除本人内容”流程移除的内容也不能用普通恢复操作重新公开。

### 保留策略与保全

“保留矩阵”设置各受管类型的保留天数、是否允许可恢复删除、是否允许恢复和是否支持保全。保留天数留空表示无限期保留，不是立即清理。修改策略需要记录原因，并考虑正在处理的案件及现有保全。

“保留保全”用于记录必须保存某项内容的原因、案件或策略引用及可选到期时间。设置和释放保全都需要相应权限和原因；不能为了清空回收记录而随意解除仍有业务依据的保全。

### 永久清理社区内容

永久清理要求内容已软删除、策略允许且保留期结束，同时不能存在有效保全、未结举报、审核案件或其他适用的证据阻断。日期到达并不意味着所有条件都满足，手动操作也不能跳过这些检查。

核对资源、原因和不可逆后果后再提交。关户内容中用于维持共同讨论结构的容器可能继续保留；不要通过直接删库消除阻断。遇到错误时保存记录编号和阻断原因，先处理来源问题。

证据附件还受独立的访问、扫描和保留规则保护，见[审核、案件与证据](/docs/staff/moderation-and-evidence/)。Minecraft 世界处理见[世界备份与恢复](/docs/operations/minecraft-world-recovery/)。
