工作人员工作台把待审内容、举报、附件隔离和用户风险事件汇总为可审计案件。只处理自己有权查看的范围；缺少权限时，不应通过他人的链接或账户查看材料。

## 标准流程

1. 检查案件风险、来源、当前状态、指派和同步警告。
2. 认领或由有权限的人员指派，避免多人同时处置。
3. 阅读原始内容、可见证据和既有备注；缺失或不可读证据不能当作“没有证据”。
4. 只选择页面当前允许的动作，并在执行前核对目标、范围和影响。
5. 记录事实、依据和后续责任人，不把密码、密钥或无关个人信息写入备注。

## 举报结果与复议、申诉

举报详情中的原始证据与内部备注，不等于举报人最终能看到的内容。结案后，举报人通过“我的举报”和账户通知查看经过限制的公开结果；不要把内部材料复制到公开回复中。

工作人员从“举报复议与申诉队列”（`/app/staff/report-appeals`）处理已经提交的申请。具备后台相应权限的管理员也可从“论坛 → 举报复议与申诉”进入。

1. 按状态筛选，打开当前有权复核的申请。
2. 区分“申请人可见内容”和“受保护的举报上下文”，核对申请角色、原结案结果和新理由。
3. 查看申请人证据，必要时按页面提供的入口添加仅审核人员可见的证据。
4. 选择“维持原决定”或“撤销原决定”，填写必要的内部说明，再记录决定。
5. 如果还需要恢复内容、解除限制或其他操作，交由具有该项权限的人员在相应流程继续处理。

申请人、原举报人或直接受影响的用户不能审核自己的相关申请。板块版主只可复核管辖范围内事项；私信举报需要独立的私信举报审核权限。未提交草稿不会进入工作人员队列。

“撤销原决定”只记录本次复核结论并通知申请人，不会自动撤销独立的禁言、封禁、内容删除等站务处置。不要把结论已记录写成所有后续措施都已完成。

## 证据附件

证据上传后先等待安全扫描。文件显示“可用”后，仍需按对应页面操作将其加入案件；上传完成不一定等于已经作为证据提交。

注意附件的可见范围：申请人与审核人员可见的材料，与仅审核人员可见的内部证据分开处理。不要把普通附件链接当作对外分享授权。

尚未加入案件的附件可在页面允许时丢弃。已保全的证据、隔离文件或受账户关闭等保留规则影响的文件，可能禁止删除；需要永久清理时遵守对应权限和保留限制，见[内容回收、保留与清理](/docs/admin/content-recovery/)。

同步警告表示案件展示可能不是最新状态。先刷新或联系运维，不要在未知状态下重复执行高风险动作。
