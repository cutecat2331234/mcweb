# McWeb 产品功能与前端体验开发总计划

> 状态：实施中
> 最近源码与计划复核：2026-07-29
> 范围：CE 共享产品功能、共享管理后台体验，以及 EE 专属公众社区功能与 EE `/app`
> 不包含：部署、容器、主机、域名、证书、对象存储选型、备份/恢复演练、灾备、监控告警、容量运维、值班和发布流程

## 1. 使用方式

本文是“只算功能开发”的统一执行入口。现有
[`code-completion-and-developer-mode-plan.md`](code-completion-and-developer-mode-plan.md)
和 [`production-readiness-backlog.md`](production-readiness-backlog.md) 继续记录代码底座、
安全、发布和生产运维事项；EE 的详细设计继续保存在
`mcweb-ee/docs/ee-missing-feature-development-plan.md`。开发产品功能时以本文确定优先级、
版本边界和体验门禁，再到原详细计划核对数据模型与安全约束。

每个功能必须按“数据与状态 → 服务与权限 → API/任务/实时 → 审计 → 前端 →
I18N/无障碍 → 自动测试 → 浏览器验收”形成纵向闭环。只有页面、按钮、模型或路由均
不能单独算完成。

### 1.1 状态

| 状态 | 含义 |
|---|---|
| 未开始 | 还没有可独立使用和验收的纵向功能切片 |
| 实施中 | 已开始开发或已有部分底座，但用户流程尚未闭环 |
| 阻塞 | 必须等待明确的功能依赖，不能提前开放入口 |
| 已验证 | 后端、权限、审计、前端、翻译、自动测试和浏览器场景均有证据 |

### 1.2 优先级

- **P0**：公开提供产品前必须完成；包含资金风险、权限泄漏、关键审核、实时正确性和
  当前严重影响使用的前端问题。
- **P1**：正式版产品完整性；缺少时可以有限预览，但不能宣称功能完整。
- **P2**：核心闭环稳定后的增强能力。

## 2. 版本边界

- CE `main` 是所有共享能力的唯一上游。共享模型、服务、权限、管理后台和通用修复
  必须先进入 CE，再由 EE 精确合并该提交历史。
- EE 必须始终包含目标 CE 提交的完整祖先历史；EE 专属提交只能追加在共享提交之后。
- CE 用户前台 `/app` 保留当前组件栈和产品风格，本计划不把 EE 用户前台反向移植到 CE。
- CE 不包含 `/cable`、WebSocket 客户端、实时论坛广播、空间/频道聊天、输入状态或
  其他 EE 实时运行时代码。
- EE 是面向公众社区的付费版，不是企业内部办公软件；不开发 HR、审批、考勤、内部
  通讯录或企业工单。
- EE `/app`、CE/EE 管理后台和未来插件管理界面使用 Arco Design Vue；共享后台使用
  `@mcweb/ui`，不得再引入另一套一次性组件库。

## 3. 明确排除

下列事项即使会影响生产发布，也不计入本文的功能开发进度：

- Docker、Kubernetes、systemd、反向代理、TLS、主机或网络配置。
- 数据库、Redis、Worker、对象存储的部署、扩容、跨区域和故障切换。
- 备份介质、RPO/RTO、灾备演练、异地复制和恢复值班。
- 指标平台、日志平台、Tracing、监控图表、告警路由和事故响应流程。
- 发布包、版本标签、灰度、回滚和环境密钥注入。
- 仅用于开发人员的诊断面板、测试环境搭建和纯 CI 优化。

可靠事件、断线补拉、幂等写入和权限立即失效仍保留在 EE 功能计划中，因为它们直接
决定用户能否“不刷新页面也看到正确内容”；但本文不规划其 Redis 拓扑、部署和监控。

## 4. 所有功能共同的前端体验基线

### 4.1 视觉层级与色彩

- 页面至少区分画布、功能分区和交互表面三个层级，禁止背景、卡片、表格和输入框全部
  使用同一种灰白色。
- 主色只用于当前导航、主操作、链接和焦点；成功、警告、危险、信息使用稳定语义色；
  普通内容保持中性色，避免为“更丰富”而堆成彩虹。
- 关键数据使用图标、数字、Tag、Badge、进度或轻量强调面，不再只靠一排相同文字。
- 选中、悬停、禁用、无权限、异常和待处理状态必须有可辨识的颜色、图标和文案差异，
  且不能只依赖颜色传达含义。
- 用边框、背景层、留白和轻量阴影共同建立层级；禁止为每一段内容再套一层同样的方框。

### 4.2 方正与圆角混用

- 应用壳、数据密集表格、权限矩阵和分隔结构保持方正或小圆角，表达稳定结构。
- 页面分区、内容卡、空状态和重要摘要使用中等圆角，避免当前大量硬直角带来的生硬感。
- 输入框、按钮、搜索框和工具条使用适度圆角；Tag、Badge、状态点和 Avatar 才使用
  胶囊或圆形。
- 推荐层级为：壳/表格 `4px`，分区 `8px`，内容卡/浮层 `10–12px`，控件 `6–8px`，
  胶囊/圆形仅用于小型语义元素。实际实现应使用统一 token，不在页面随机写数值。
- 同一视图必须同时保留结构边界和柔和内容面，不能把所有组件都改成圆角卡片。

### 4.3 布局、密度与响应式

- 统一使用 `4/8/12/16/24/32px` 间距体系；标题与说明、表单项、卡片、工具栏和表格行
  分别使用稳定密度，禁止一处挤压、一处出现巨大空白。
- 页面只保留一个主滚动责任；侧栏、内容区、Drawer 和 Modal 明确各自滚动，避免双滚动、
  截断、超高空白和整页横向滚动。
- 版主工具、权限解释、筛选、置顶、搜索和修订历史使用 Drawer、Modal、Tabs 或独立页；
  禁止用长 Collapse 把正文页无限拉长。
- 桌面表格在窄屏改为卡片、列表或可控横向滚动；主要操作不能只在 hover 出现。
- 长用户名、长频道名、长翻译、长正文、大图片和大量 Tag 必须换行或省略并提供完整信息。
- SPA 导航、筛选、提交、实时更新和错误恢复不得重新挂载整个页面；只有登录状态根本改变、
  应用版本不兼容或明确不可恢复时才允许硬刷新。

### 4.4 Arco 与自定义样式边界

- 优先使用 Arco 的 Layout、Menu、PageHeader、Breadcrumb、Tabs、Table、List、Card、
  Descriptions、Statistic、Form、Drawer、Modal、Alert、Result、Empty、Skeleton、
  Spin、Pagination、Tag、Badge、Avatar、Tooltip、Trigger、Upload 和 Timeline。
- 自定义 CSS 只用于产品壳层、响应式网格、滚动责任、safe-area、品牌 token 和组件库
  无法表达的布局；不得复刻已有 Arco 组件或为单页制造另一套视觉系统。
- 共享管理后台的主题、间距、圆角和表面 token 在 CE 定义，EE 通过合并继承。
- EE `/app` 直接使用 Arco 组件完成业务界面，不把一组原生 `div` 加自写样式伪装成组件。

### 4.5 文案、I18N 与可访问性

- 删除“这里按照开发要求实现”“企业版将提供”“功能规划中”等面向开发者的说明；
  未完成的入口隐藏，不能把计划文案展示给终端用户。
- 不直接显示配置 key、权限 key、异常类名或数据库状态；转成用户能理解的名称、说明和
  下一步操作。
- 所有可见文案、校验错误、空状态、确认提示和通知进入 `zh-CN`/`en` 词典；中文环境
  不得出现未翻译英文或原始 key。
- 键盘操作、可见焦点、ARIA 名称、标题层级、对比度、Reduce Motion 和屏幕阅读器状态
  必须随功能一起完成。
- 每个页面验收正常、加载、空数据、错误、无权限、离线/重连、长内容、桌面、平板和手机。

### 5.1 `SHARED-UX-001`：管理后台视觉层级与交互壳统一

子功能：

- 建立共享画布、分区、卡片、表格、控件、语义状态和浮层 token。
- 优化导航选中态、页面标题区、摘要数据、主次操作、筛选区和内容分区。
- 统一圆角层级、间距、边框、阴影、暗色模式和动效降级。
- 清理页面级重复壳、内联样式、双滚动、固定高度和会导致错位的局部补丁。
- 把复杂工具移入 Drawer/Modal/Tabs；保留当前内容上下文和滚动位置。
- 表格、筛选、分页和提交使用局部状态更新，不以整页刷新作为成功反馈。

验收：

- 仪表盘、系统设置、用户/角色/身份组、论坛审核和商城管理采用同一视觉语言。
- 1280px、1024px、768px 和 390px 下无重叠、截断、异常留白或不可达操作。
- 页面同时具有清晰重点和克制配色，且不会变成“每块都是一张圆角卡”。
- 后退/前进、切换页签、保存和失败重试不重挂载整个后台壳。

### 5.2 `SHARED-I18N-001`：用户文案、I18N 与无障碍闭环

子功能：

- 扫描业务 Vue/Ruby 可见硬编码文案，补全 `zh-CN`/`en`，并阻止新硬编码回流。
- 将系统设置 key、权限 key、错误码和技术状态映射为可理解的名称与帮助文案。
- 人工复核支付、余额、权益、权限、审核、封禁和删除等高风险文案。
- 为 Modal、Drawer、菜单、表格、分页、上传、通知和实时状态补齐键盘与 ARIA 语义。
- 统一空状态、无权限、加载、失败、重试和成功反馈，不使用开发计划或占位文案。

验收：

- 中文页面不出现原始英文 key，英文页面不出现硬编码中文。
- 仅使用键盘可完成关键查询、表单、确认、关闭浮层和返回内容。
- 主要文字、状态、焦点和交互控件达到可辨识对比度，Reduce Motion 生效。

### 5.3 `SHARED-FINANCE-001`：人工余额/权益调整安全闭环

子功能：

- 将查看、调整余额、授予权益、撤销权益拆成独立权限；`admin.access` 不作为写操作兜底。
- 服务端生成短期、单次、绑定操作者/目标/动作/数值的确认挑战，不能只依赖前端弹窗。
- 调整请求要求业务理由、幂等键和 request id；重复提交只产生一次结果。
- 在同一事务写入余额或权益变化、不可变流水和脱敏审计前后值。
- 用户详情以 Arco Drawer/Modal 展示当前值、变更预览、风险提示和最近流水。
- 金额、单位、正负方向、上限、零值和并发冲突提供明确校验与翻译。

验收：

- 无独立权限、确认过期、确认被重放、目标变化和并发提交均不会改变资产。
- 成功后可按操作者、目标用户、request id 和业务理由追溯同一事件。
- 手机端可完成确认但不会误触；失败保留输入与理由，不刷新整个用户页面。

### 5.4 `SHARED-MOD-001`：统一审核与用户风险工作台

子功能：

- 聚合待审核主题/回复、举报、垃圾命中、附件隔离和用户风险事件。
- 提供来源、类型、状态、优先级、板块、处理人、时间和风险维度筛选。
- 支持领取、转派、备注、释放、删除、移动、警告、禁言和封禁的细粒度权限。
- 批量动作要求影响预览、理由、幂等键、二次确认和逐项结果。
- 证据快照与普通内容读取分离；无证据权限者看不到私密或已删除内容。
- 使用列表/表格作为主工作区，详情和版主工具使用 Drawer，避免展开后拉长整页。

验收：

- 同一对象不会被重复处置；并发审核给出冲突和最新状态。
- 四类角色（管理员、版主、只读审核员、无权限用户）看到准确入口与动作。
- 空队列、大队列、长证据、附件加载失败和手机端均可正常处理。

### 5.5 `SHARED-ATTACH-001`：附件扫描误报人工放行

子功能：

- 单独定义“人工放行”权限，不复用重新扫描、清理重试或普通审核权限。
- 只允许明确支持人工判定的扫描结果进入放行候选；危险文件类型始终拒绝。
- 放行必须填写理由，保存扫描器结果、文件摘要、操作者和前后状态。
- 放行状态、下载策略、重新扫描和后续撤销具有明确状态机与幂等行为。
- 在附件隔离工作台以 Modal 展示最小安全预览、风险说明和确认。

验收：

- 无权、状态不允许、文件已变更、重复放行和并发重新扫描全部 fail closed。
- 放行记录不可变且可撤销；旧签名下载地址不能绕过新状态。
- 用户只看到可理解结果，不看到扫描器内部命令或存储路径。

### 5.6 `SHARED-DATA-001`：内容保留、删除、保全与用户导出

子功能：

- 为主题、回复、私信、附件、通知、审核证据和审计记录建立保留矩阵。
- 区分用户删除、版主软删除、恢复、管理员永久清理和 legal hold。
- 未结举报、争议、审计引用和保全可阻止永久清理，并说明阻止原因。
- 用户数据导出异步生成、可重试、可撤销、限时下载并记录审计。
- 账号删除支持内容删除、稳定匿名作者和依法保留三种明确结果。
- 管理界面使用 Steps/Progress/Result 展示任务，不暴露磁盘路径或签名密钥。

验收：

- 删除/恢复/清理重试幂等，引用完整，附件与正文状态一致。
- 无权用户不能通过错误差异推断已删除或受保全内容。
- 超大导出、任务失败、过期下载和重复匿名化有自动测试。

### 5.7 `SHARED-STOCK-001`：库存流水、预留与异常恢复

子功能：

- 建立不可变库存流水，记录来源订单、SKU、数量、原因、操作者和 request id。
- 区分可售、已预留、已售、退回、损坏和人工调整，不再只保存最终数量。
- 预留带过期时间，支付成功确认占用，取消/超时幂等释放。
- 提供异常预留、负库存、订单与库存不一致的查询和恢复动作。
- 人工调整使用独立权限、影响预览、理由和二次确认。
- 后台以 Statistic、Timeline、Table 和 Drawer 突出可售、预留和异常，而非同色表单。

验收：

- 并发下单、支付超时、晚到支付、取消、退款和任务重试不超卖、不重复释放。
- 任意库存值可由流水重算；人工恢复可追溯且不覆盖原历史。

### 5.8 `SHARED-FULFILL-001`：履约失败恢复与人工重放

子功能：

- 履约任务保存状态、尝试次数、下次执行、稳定幂等键和外部结果摘要。
- 超过重试上限进入可查询失败队列，不永久卡在处理中。
- 人工重放前重新校验订单、支付、库存、退款和现有权益。
- 支持取消不可再执行任务，展示阻止原因和建议动作。
- 详情 Drawer 用 Timeline 展示每次尝试；重放使用独立权限、理由和确认挑战。

验收：

- Worker 中断、超时、外部成功但本地提交失败和重复重放不会重复发货或授予权益。
- 管理员无需查看日志即可理解失败原因、当前状态和可执行下一步。

### 5.9 `SHARED-RISK-001`：争议、拒付与支付风险处置

子功能：

- 建立争议/拒付状态机、渠道事件、证据截止时间、责任人和处理结果。
- 关联订单、付款、退款、履约、库存与权益，避免各页面状态互相矛盾。
- 按策略冻结或撤销权益，保留人工复核和恢复路径。
- 提供分派、备注、提交证据、接受损失和关闭事件的独立权限与审计。
- 使用 Alert、Descriptions、Timeline、Tag 和 Drawer 突出时限、金额和风险等级。

验收：

- 重复/乱序渠道事件、部分争议、退款后争议和撤销争议均保持金额与权益守恒。
- 高风险动作显示真实影响并需要二次确认；普通客服看不到支付敏感字段。

### 5.10 `SHARED-FINANCE-002`：税费、发票、退款凭证与财务导出

子功能：

- 订单快照保存税率、税额、计税基础、币种、舍入和适用地区。
- 发票与退款凭证使用稳定编号、版本和状态，禁止静默覆盖已出具记录。
- 财务导出支持时间、渠道、币种、状态和税务维度，异步生成并限时下载。
- 定义订单、付款、退款、发票和导出文件的产品保留规则。
- 管理页提供筛选、汇总、明细深链和导出进度，不在页面堆叠原始配置字段。

验收：

- 部分退款、多次退款、跨日对账和舍入场景金额一致。
- 重复生成不会产生重复编号；导出内容、权限和下载过期均有测试。

### 6.1 实时、权限与审计

#### `EE-RT-001`：实时能力统一门禁与安全降级

- 同时检查 EE 授权、实时总开关、实时使用权限和具体资源读取权限。
- Cable 连接、订阅、论坛流、事件补拉和通知任务使用同一门禁。
- 统一版本化事件信封，只携带定位和局部刷新所需的最小字段。
- 实时暂停时保留 REST 浏览并显示真实降级状态，不伪装在线。
- 验收关闭功能、无授权、撤权、封禁和会话失效均不能继续订阅。

#### `EE-AUTH-001/002`：细粒度权限、解释与立即失效

- 覆盖空间、分类、频道、消息、线程、成员、角色、审核、附件、反应、表情和提及权限。
- 每个写服务重复授权；三态覆盖使用继承/允许/拒绝，并显示最终来源链。
- 操作者只能委派自己拥有的权限，不能管理同级/更高角色或移除最后所有者。
- 每次授权变化递增版本，使 HTTP、现有连接、后台任务和待发送私密通知同时失效。
- 管理员可查看“为什么拥有/没有”与成员视角预览，前端不复制权限算法。
- 验收每个执行点具备允许、拒绝、继承、资源不匹配和直接 API 越权测试。

#### `EE-AUDIT-001`：聊天审计、查询与保留

- 记录空间、频道、角色、成员、覆盖、消息、举报、制裁、通知、邀请和 Bot 动作。
- 记录 actor、subject、resource、前后值、理由、IP、request id 和 event id，并脱敏。
- 成功审计与业务同事务；拒绝、限流和高风险失败明确记录为失败事件。
- 后台按操作者、资源、动作和时间查询，提供权限受控导出。
- 验收可从操作者、成员、资源和 request id 追踪同一事件，且不记录 token/正文密钥。

### 6.2 空间、频道、角色与成员

#### `EE-CRUD-001`：空间生命周期

- 编辑名称、稳定标识、图标、简介、加入策略和默认频道。
- 支持归档、恢复、软删除、清理和所有权转移，并保护最后所有者。
- 删除前展示成员、频道、消息、附件和邀请影响；并发编辑使用资源版本。
- 管理入口使用 Form/Descriptions/Drawer/Modal，手机端不依赖 hover。
- 验收归档后 HTTP 与实时发送均被拒绝，冲突不静默覆盖。

#### `EE-CRUD-002A/B`：分类与频道生命周期及跨端收敛

- 编辑、移动、排序、归档、恢复和安全删除分类/频道。
- 分类删除时明确移动频道、归档频道或取消；排序在单一事务校验。
- 频道支持类型、主题、慢速模式、默认通知和权限覆盖。
- 结构事件使侧栏、当前频道、搜索范围、深链和订阅局部更新，不整页刷新。
- 当前资源消失时隔离草稿、导航到安全位置并清除无权标题/预览。
- 验收并发排序、乱序/重放和多浏览器结构变更最终一致。

#### `EE-CRUD-003`：角色与成员生命周期

- 角色支持创建、复制、编辑、排序、删除、批量分配和撤销。
- 成员覆盖 invited、active、left、kicked、banned 和 deleted-account。
- 支持踢出、临时/永久封禁、解封和重新加入，制裁保存原因、证据和到期。
- 历史消息保留稳定作者引用；临时封禁到期和权限撤销幂等生效。
- 验收普通管理员不能操作同级以上角色，所有变化即时影响 HTTP/Cable/UI。

#### `EE-ADMIN-001`：独立 Arco 聊天管理台

- 建立 `/admin/chat`，按空间、频道、成员、角色、覆盖、审核、通知和审计组织。
- 列表使用 Table/Filter/Pagination/Tabs，简单编辑用 Modal，复杂编辑与影响预览用 Drawer。
- 版主工具不得通过长 Collapse 拉长页面；手机端使用全屏 Drawer。
- 导航、页签和动作分别按真实权限控制，不显示权限 key、开发说明或未完成功能。
- 验收管理员、版主、只读审计员和无权限成员四种浏览器矩阵。

### 6.3 消息安全、历史、审核与规模

#### `EE-SAFETY-001`：屏蔽、静音与禁言

- 明确定义 block、用户侧 mute 和版主 timeout 的对象、范围、到期及解除。
- 屏蔽抑制普通提及、通知、建议与补全，但不泄露对方屏蔽关系。
- 审核证据和合法审计不被普通屏蔽绕过；审核员查看需独立权限和记录。
- HTTP、Cable 和服务层一致执行 timeout；到期幂等解除。
- 用户设置、频道菜单和成员菜单提供可理解入口及可访问折叠占位。

#### `EE-HISTORY-001`：消息修订、删除与恢复

- 每次编辑保存稳定版本、编辑者、时间、原因和最小必要快照。
- 区分作者删除、版主删除、系统隔离和最终清理；支持权限受控恢复。
- 未结举报、附件证据和 legal hold 可以阻止清理。
- 修订历史与恢复工具使用 Drawer/Modal，不改变消息列表高度。
- 验收并发编辑提示冲突，编辑/删除/恢复跨端幂等收敛且不泄露审核信息。

#### `EE-MOD-001/002`：举报、慢速模式、限流与反垃圾

- 消息举报支持分类、说明、证据快照、分派、状态、处置和申诉关联。
- 服务端按账号、IP、空间、频道和操作执行限流，返回统一 `Retry-After`。
- 频道慢速模式保存间隔，明确版主豁免权限并在服务层执行。
- 提及数量、重复内容、链接和洪泛规则支持观察、拦截、隔离和审核释放。
- 审核中心使用 Table + Drawer/Modal；命中依据、风险值和正文按权限隔离。
- 验收直接 API、并发发送、多标签页、重连重试和释放重放均不能绕过或重复发布。

#### `EE-SCALE-001`：长频道、成员与未读体验

- 成员使用稳定游标分页，支持角色、状态和名称筛选。
- 空间结构批量返回可见频道未读/提及摘要，禁止逐频道请求。
- 100+ 频道、1000+ 成员和长消息历史使用虚拟列表或分页。
- 加载更多保持选中项、草稿和滚动锚点；骨架尺寸稳定，不产生跳动或巨量空白。
- 验收筛选、分页、低速网络、10k 消息历史和断线补偿都不重挂载 `/app`。

### 6.4 草稿、链接、通知与可靠事件

#### `EE-DRAFT-001`：草稿与导航状态隔离

- 草稿按账号、空间、频道和线程隔离并持久化。
- 切换、前进后退、发送失败、429 和抽屉开关都保留正确草稿。
- 成功只清除当前目标草稿；撤权/离开/资源删除把草稿移入不可自动恢复隔离区。
- History state 不保存正文或私密标题；恢复时校验当前权限和资源版本。
- 验收多标签页、跨频道慢响应和权限变化不会覆盖或泄露其他草稿。

#### `EE-LINK-001B`：规范深链与状态恢复

- 为通知、置顶、搜索和审核提供统一 link builder/解析契约。
- 路由不只依赖可变 slug；改名后的旧链接安全定位或规范跳转。
- 恢复筛选、线程和准确滚动锚点，不重置草稿或页面壳。
- 删除、归档、移动和撤权返回同形安全结果，避免资源枚举。
- 验收旧链接、浏览器前进后退、跨空间 ID 和撤权场景。

#### `EE-NOTIFY-001`：分层通知、未读与免打扰

- 用户、空间、频道三级偏好，支持全部、仅提及、无通知和临时静音。
- 支持 DND 时段、时区、角色/全体提及开关和线程回复规则。
- 事件、通知记录和已读游标分别持久化；刷新、重连和换设备保持一致。
- 投递前重新检查读取权限、成员/封禁/屏蔽状态。
- 设置页显示最终值与继承来源；通知中心通过规范深链定位消息。

#### `EE-RT-002`：可靠事件、断线补偿与背压

- 业务写入与事件同事务，事件包含聚合、序列、版本、最小 payload 和重试状态。
- 客户端按频道保存游标；重连补拉缺失事件，超出窗口只刷新安全局部快照。
- client nonce 关联超时/离线发送结果；编辑、删除、反应、置顶和撤权可重放。
- HTTP 写入不再同步遍历全部成员；用户通知异步分片。
- typing/presence 可丢弃过期状态，关键消息和权限事件不得静默丢失。
- 验收断网、休眠、任务暂停和服务重启后无需整页刷新且不重复消息。

### 6.5 P1 产品完整性

#### `EE-DISCOVERY-001`：空间发现、申请、加入与离开

- 支持 private/request/public 策略、公开目录、安全摘要、申请、审批、离开和重新申请。
- 申请保存规则版本、留言、处理人、理由和时间；并发审批不重复加入。
- 未加入用户看不到私密频道、成员、活动和在线信息。
- 使用 List/Card/Filter/Modal/Steps 展示规则和状态，不显示开发文案。
- 验收封禁重入、规则变化、默认频道不可见和重复申请。

#### `EE-INVITE-001`：安全邀请

- 邀请保存摘要、过期、次数、绑定对象、预授角色和使用日志；明文仅展示一次。
- 提供创建、撤销、重新生成、接受、列表和使用历史。
- 邀请人不能预授高于自身或自己没有的角色。
- UI 展示剩余次数、到期和撤销状态，手机端复制/撤销不依赖 hover。
- 验收并发使用最后一次、过期、撤销、重放、绑定不符和邀请人撤权。

#### `EE-ATTACH-001`：消息附件

- 上传会话绑定空间、频道、用户和待发消息，覆盖扫描、隔离、就绪和删除状态。
- 服务端识别类型、图片重编码、用户/消息/空间配额和孤儿回收。
- 私密下载每次重新授权，使用短期链接、安全响应头和撤权失效。
- Composer 支持选择、拖拽、粘贴、进度、取消、失败重试和发送前预览。
- 验收伪 MIME、超额、扫描失败、重复完成、撤权下载和消息事务失败。

#### `EE-REACT-001`：消息反应

- message + user + emoji 唯一，添加/撤销幂等，聚合以服务端事实为准。
- 删除、隔离、封禁、撤权和表情停用后禁止新增。
- 使用 Trigger/Popover，手机端有长按或明确按钮，不改变消息行高度。
- 实时事件携带最终聚合与 event id；验收并发、多设备和重放一致。

#### `EE-PIN-001`：消息置顶

- 保存消息、操作者、时间、备注和状态，提供置顶、取消和游标列表。
- 独立权限控制；读取置顶仍需当前频道权限。
- 置顶面板使用 Drawer/List，不用 Collapse 拉长消息页。
- 通过可靠事件跨端同步，点击使用统一深链；验收删除、恢复、撤权和归档。

#### `EE-SEARCH-001`：权限安全消息搜索

- 支持关键词、作者、空间、频道、日期、线程和附件筛选与稳定分页。
- 先计算可见频道范围再搜索、计数、建议和高亮，禁止前端过滤私密结果。
- 编辑、删除、恢复、隔离和撤权可靠更新可见索引。
- 桌面使用 Drawer/独立面板，手机全屏 Drawer；定位结果不清草稿、不整页刷新。
- 验收私密关键词、计数、建议、片段和跨空间 ID 均不泄露。

#### `EE-NOTIFY-002`：离线提及

- 站内通知必备，邮件/Web Push 可选；投递任务有稳定幂等键和取消原因。
- 延迟窗口内已读则取消；入队和发送前都重新检查权限、DND、mute 和 block。
- 锁屏/邮件正文遵循隐私设置，默认使用安全摘要。
- 验收刚离线、跨午夜 DND、撤权、消息编辑/删除、重试和多设备去重。

#### `EE-PRESENCE-001`：可信在线状态

- 定义 online、idle、dnd、invisible 的多标签/多设备聚合和过期规则。
- Presence 只在共同可见空间传播；隐身对普通成员始终表现为离线。
- 完成前移除不可信“在线”文案；完成后用 Badge/Avatar/Tooltip 表达状态和可信度。
- 验收关闭单标签、崩溃过期、休眠唤醒、网络切换、撤权和跨空间枚举。

#### `EE-DATA-001`：聊天导出、保留与匿名化

- 用户/空间导出、加密临时文件、重试、过期清理和审计。
- 为消息、附件、修订、通知和短期 Presence 建立保留矩阵。
- 账号删除区分删除内容、匿名作者与举报/legal hold 保护。
- 使用 Steps/Progress/Result 展示状态，不暴露存储路径。
- 验收大导出、撤销下载、重复匿名化、引用完整和保全冲突。

### 6.6 P2 增强
