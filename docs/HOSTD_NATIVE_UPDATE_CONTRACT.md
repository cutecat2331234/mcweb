# Hostd 原生更新入口交付合同

## 归属与边界

本能力归属 **CE**。宿主机 release 下载、候选版本暂存和安全更新调用是所有版本共享的
主机生命周期原语，不包含 EE 或 PVP 业务概念。下游只能通过 `CE -> EE -> EE-PVP`
继承这段历史，不得复制实现。

本次只修复原生部署的 hostd 更新入口。Docker Compose 的 `pull` / `up -d` 行为、
首次安装向导、备份格式和 `bin/update` 内部的迁移及回滚策略不在本次改动范围内。

## 已确认问题

旧入口会下载 `mcweb-<version>.tar.gz`，但不下载或验证发布包的 SHA-256 文件，
也不把归档安全解包到 `/opt/mcweb/releases/<version>`。随后它无参数执行当前版本的
`bin/update`。安全更新脚本要求同时提供：

```text
--release /opt/mcweb/releases/<version> --confirm UPDATE:<version>
```

因此旧的原生更新入口无法满足当前安全合同，并且在包完整性、归档路径和候选目录
发布方面缺少失败关闭边界。

## 功能需求清单

### 输入与来源

1. 原生更新必须明确提供 `version`；空值不得退化为无参数更新。
2. `version` 只能使用 ASCII 字母、数字、点、下划线和连字符，必须以字母或数字开头，
   且不能为 `.` 或 `..`，从而不能参与路径穿越或命令构造。
3. `release_url` 是发布下载基地址。资产地址固定为：
   `<release_url>/<version>/mcweb-<version>.tar.gz` 及其 `.sha256`。
4. 公网来源必须使用 HTTPS；仅允许 `localhost`、`127.0.0.1` 和 `::1` 在测试或受控
   本机环境中使用 HTTP。
5. 下载必须具备超时、HTTP 状态检查和大小上限；日志不得记录凭据或 URL 查询参数。

### 完整性与解包

1. `.sha256` 必须包含 64 位十六进制摘要，摘要与下载归档不一致时立即失败。
2. 解包只能接受预期根目录内的普通文件和目录；拒绝绝对路径、`..`、重复条目、
   符号链接、硬链接、设备、FIFO 及其他特殊类型。
3. 对归档条目数量、单文件大小和总解包体积设置硬上限，避免资源耗尽。
4. 解包过程只发生在 releases 目录内的唯一临时目录；任何预发布失败都清理临时目录。
5. 目标候选目录已存在（包括符号链接）时必须拒绝覆盖。

### 更新调用与失败语义

1. hostd 自身绝不修改 `current` 或 `previous` 指针；它只发布候选目录并调用候选版本
   内已加固的 `bin/update`。
2. 调用必须准确传递候选绝对路径与 `UPDATE:<version>`，不能调用当前版本更新脚本，
   不能通过 shell 拼接参数。
3. 下载、校验、解包或候选校验失败时，`current` 完全不变，且不会调用更新脚本。
4. `bin/update` 返回失败时，hostd 报告失败并保留候选目录供管理员审计；当前链接的
   恢复由 `bin/update` 的既有原子回退合同负责。数据库 migration 已执行后不会自动
   向下迁移，管理员必须按生产手册检查 schema 兼容性。
5. 日志可以记录无敏感信息的版本、阶段和目标路径，不得展开运行环境、凭据或带查询
   参数的下载 URL。
