# McWeb 功能生产就绪门禁

> 状态：持续实施
> 最近复核：2026-07-29
> 适用范围：McWeb CE 与作为其下游的 McWeb EE

## 1. 文档目的

本文只回答一个问题：从产品功能开发角度，McWeb 当前是否可以直接作为公众产品投入
生产使用，以及尚缺哪些功能闭环。

本文明确不统计以下事项：

- 部署方式、容器、域名、TLS、对象存储和邮件基础设施。
- 备份、恢复、灾备、监控、告警、容量规划和运维值班。
- 纯视觉审美问题。
- EE 专属实时与频道功能在 CE 中的缺失；CE 本来就不得包含这些能力。

纯视觉调整不单独计为功能。但是，如果界面问题导致操作不可达、错误结果、误触危险动作、
无法在手机或键盘环境完成流程、显示原始技术 key，仍视为功能未闭环。

详细开发拆分以
[`functional-development-plan.md`](functional-development-plan.md) 为准；共享论坛、商城和
后台的旧生产待办以
[`production-readiness-backlog.md`](production-readiness-backlog.md) 为补充；插件平台以
[`PLUGIN_SYSTEM_ROADMAP.md`](PLUGIN_SYSTEM_ROADMAP.md) 为准。本文是三者之上的功能发布门禁
视图，不取代它们。

## 2. 当前结论

| 产品范围 | 当前结论 | 说明 |
|---|---|---|
| CE 官网与论坛，关闭真实资金商城 | 只能考虑受控灰度 | 共享后台、审核、数据生命周期和关键浏览器流程仍未完全闭环 |
| CE 开启真实资金商城 | 不可直接生产上线 | 人工资金/权益动作、库存、履约恢复和财务风险流程仍有缺口 |
| EE 付费公众社区 | 不可直接生产上线 | 可靠实时、多人治理、屏蔽/通知、频道管理和审计等 P0 尚未完成 |

即使把 EE 当前工作树中的在途代码计入，上述结论也不改变。当前在途代码已经显著补强
实时门禁、空间生命周期、消息历史、举报处置、临时封禁和慢速模式，但还没有覆盖本文件
列出的全部 P0。

## 3. 版本边界

- 共享功能必须先进入 CE，再由 EE 合并 CE 的完整提交历史。
- EE 是 CE 的 Git 下游，EE 的最终提交历史必须包含最新 CE `main`。
- CE 用户前台维持现有社区前端，不因 EE 重写而改成 Arco。
- 共享管理后台使用统一的 Arco 视觉与交互语言。
- EE `/app`、Action Cable 实时论坛、Discord 类空间/频道聊天和频道实时事件只属于 EE。
- 未完成功能必须隐藏或明确关闭，不能显示无效入口、假在线状态或开发计划文案。

## 4. 已有功能基础

以下能力已经存在，后续工作应补齐闭环而不是重复实现：

### 4.1 CE 共享基础

- 注册、登录、邮箱验证、密码重置、TOTP 和会话撤销。
- 论坛分区、主题、回复、搜索、订阅、通知、举报、审核、私信、投票、反应和附件。
- 商城目录、购物车、订单、支付回调、退款、优惠券、礼品卡、余额、会员商品和数字权益。
- 真实支付会话、Webhook 验签、支付/退款幂等、晚到支付和对账基础。
- 附件类型识别、图片重编码、扫描、隔离、配额、清理和安全下载。
- 全局权限目录、身份组、角色委派边界和审计基础设施。

### 4.2 EE 当前在途基础

- EE 专属实时总门禁和按资源重新鉴权。
- 消息发送限流、频道慢速模式和前端重试反馈。
- 空间编辑、归档、恢复、软删除、所有权转移和删除影响预览。
- 消息编辑、删除、恢复、不可变修订历史和资源版本冲突。
- 消息举报、领取、转派、解决、驳回、删除消息和封禁成员。
- 永久/临时封禁、到期恢复和有权手动解封。
- 持久草稿、失败保留、客户端 nonce、深链和局部导航状态。

这些基础只有在自动化回归与统一浏览器验收通过，并形成可发布提交后，才可以标记为
“已验证”。

## 5. P0：上线前必须完成

### `FUNC-P0-001` 高风险资金与权益操作

当前状态：实施中。

余额调整已经具备签名挑战、幂等请求和事务审计，但人工会员/权益与部分订单动作没有采用
同等安全合同。

必须完成：

- 将余额查看、余额调整、授予权益和撤销权益拆成独立权限。
- 人工会员或数字权益授予/撤销不得继续只复用 `store.products.manage`。
- 人工标记付款、履约、取消和类似批量动作不得复用退款权限。
- 所有高风险动作要求业务理由、request id、稳定幂等键和影响预览。
- 使用短期、单次、绑定操作者/目标/动作/数值的服务端确认挑战。
- 资产变化、不可变流水和脱敏审计必须在同一事务成功或失败。
- 并发、重复提交、过期挑战、目标变化和部分失败不能产生重复资产结果。

完成门禁：

- 每类操作都有独立权限和允许/拒绝/重放/并发测试。
- 可按操作者、目标、request id 和理由追踪同一事件。
- 失败保留表单上下文，不整页刷新。

### `FUNC-P0-002` EE 可靠实时与断线补偿

当前状态：未完成；现有实现只能安全建立连接和接收在线期间的事件。

必须完成：

- 业务写入与可靠事件在同一事务形成，或采用等价的可靠 outbox。
- 事件包含稳定 event id、聚合标识、序列、资源版本和最小 payload。
- 客户端为频道、论坛和通知分别保存安全游标。
- 重连后补拉断线窗口；重复和乱序事件幂等收敛。
- 超出补拉窗口时只刷新受影响的安全局部快照，不重挂载整个 `/app`。
- 消息、编辑、删除、权限撤销和频道结构事件不得静默丢失。
- typing/presence 等短期事件可以过期丢弃，但不能冒充可靠业务状态。
- HTTP 写入不得同步遍历全部成员；大量收件人使用异步分片和背压。

完成门禁：

- 覆盖断网、休眠、服务重启、任务暂停、乱序、重放和事件窗口过期。
- 断线期间创建的消息、通知和论坛内容在恢复后自动出现。
- 权限撤销、成员移除和封禁不会继续接收补拉事件。

### `FUNC-P0-003` EE 多人空间与管理闭环

当前状态：部分后端能力存在，公众 UI 和独立后台未闭环。

必须完成：

- 成员邀请、移除、踢出、永久/临时封禁、解封和主动离开。
- 角色创建、复制、编辑、排序、删除、批量分配和撤销。
- 频道权限覆盖编辑、继承/允许/拒绝三态和最终权限来源说明。
- 分类与频道创建、编辑、移动、排序、归档、恢复和安全删除。
- 分类删除时明确移动频道、归档频道或取消。
- 当前资源被删除或撤权时，隔离草稿并导航到安全位置。
- `/admin/chat` 提供空间、频道、成员、角色、权限覆盖、通知和审计页面。
- 管理员、版主、只读审核员和无权限成员看到真实可用的入口与动作。

完成门禁：

- 新空间可以完全通过产品 UI 邀请并治理多个成员。
- 普通管理员不能操作同级或更高角色，也不能移除最后所有者。
- 手机端不依赖 hover；复杂工具使用 Drawer/Modal，不拉长页面。

### `FUNC-P0-004` EE 屏蔽、静音、禁言与通知

当前状态：未开始或仅有通用论坛能力，尚未接入 EE 聊天。

必须完成：

- 明确定义用户 block、用户侧 mute 和版主 timeout 的范围、到期及解除。
- HTTP、Cable、消息列表、提及、补全、搜索和通知执行同一屏蔽/禁言语义。
- 屏蔽关系本身不能通过错误、建议、计数或通知泄露。
- 支持用户、空间和频道三级通知偏好。
- 支持全部通知、仅提及、无通知、临时静音和 DND 时段/时区。
- 通知记录、事件和已读游标分别持久化，跨设备保持一致。
- 站内通知必备；邮件和 Web Push 可配置。
- 入队和发送前重新检查权限、成员状态、封禁、block、mute 和 DND。
- 未读提及必须定位真实消息，不能只切换频道后清零计数。

完成门禁：

- 覆盖被屏蔽用户提及、撤权后待发送通知、跨午夜 DND 和多设备去重。
- 用户刷新或重连后不会丢失未读，也不会收到已经无权读取的摘要。

### `FUNC-P0-005` 权限解释、审计、审核与消息生命周期

当前状态：实施中。

必须完成：

- 权限变更递增版本，使现有 HTTP/Cable、后台任务和待发送通知立即失效。
- 管理员可以查看最终权限的来源链和成员视角，前端不复制权限算法。
- 聊天审计覆盖空间、频道、角色、成员、覆盖、消息、举报、制裁、通知和邀请。
- 提供按操作者、资源、动作、request id 和时间查询及权限受控导出。
- 举报支持申诉关联、附件证据和证据保留规则。
- 消息历史支持编辑原因、系统隔离、legal hold 和最终物理清理。
- 未结举报、附件证据和 legal hold 可以阻止清理，并说明阻止原因。
- 反垃圾覆盖重复内容、链接、提及洪泛、观察、拦截、隔离和审核释放。
- 论坛与聊天危险审核动作要求理由、确认、处理中锁定和防重复提交。

完成门禁：

- 审计失败会回滚高风险业务动作。
- 无证据权限者看不到已删除正文、附件或私密内容。
- 并发领取、重复处置、编辑后处置和恢复均保持幂等。

### `FUNC-P0-006` 账号安全与自助恢复

当前状态：部分完成。

必须完成：

- TOTP 启用时安全地交付一次性恢复码。
- 支持查看剩余数量、重新生成、旧码立即失效和下载/复制确认。
- 提供修改邮箱、重新验证邮箱和敏感账号变更再认证。
- 提供账号关闭入口，并明确内容删除、匿名化和依法保留结果。
- 丢失 TOTP 设备时存在受审计的自助或人工恢复路径。

完成门禁：

- 恢复码不写入日志或分析事件，也不会在普通页面重复回显。
- 重放恢复码、旧会话和并发敏感操作均不能绕过最新账号状态。

### `FUNC-P0-007` 功能性 I18N、可访问性与危险操作体验

当前状态：实施中。

本项不计算颜色偏好等纯审美，只处理会阻断或误导操作的问题。

必须完成：

- 清理业务页面硬编码中文/英文和直接显示的权限 key、配置 key、内部状态或原始错误。
- 人工复核支付、退款、权益、权限、封禁、删除和审核文案。
- Modal、Drawer、菜单、表格、分页和表单具备键盘、焦点和 ARIA 语义。
- 高风险动作展示真实影响、明确主次操作和成功/冲突/失败结果。
- 加载、空数据、错误、无权限、离线和重连状态均可理解并可恢复。
- 390px 手机端不出现不可达操作、双滚动或必须依赖 hover 的控制。
- 筛选、分页、提交和失败重试不得以整页刷新作为反馈。

完成门禁：

- 中文环境不出现原始英文 key，英文环境不出现硬编码中文。
- 仅使用键盘可以完成关键查询、表单、确认和关闭浮层。
- 桌面、平板、手机与双语言 Chrome 场景统一验收。

## 6. P1：正式付费产品完整性

P1 可以在明确关闭相关入口的受控灰度中推迟，但正式版本不能宣称对应能力完整。

### `FUNC-P1-001` 共享统一审核与用户风险工作台

- 聚合待审主题/回复、举报、垃圾命中、附件隔离和用户风险事件。
- 提供来源、状态、优先级、板块、处理人、时间和风险筛选。
- 支持领取、转派、备注、释放、删除、移动、警告、禁言和封禁。
- 批量动作显示影响预览、要求理由和二次确认，并返回逐项结果。
- 证据读取与普通内容读取使用不同权限。
- 主工作区使用 Table/List，详情和版主工具使用 Drawer。

### `FUNC-P1-002` 内容保留、删除、保全与用户导出

- 为主题、回复、私信、附件、通知、审核证据和审计建立保留矩阵。
- 区分用户删除、版主软删除、恢复、永久清理和 legal hold。
- 提供异步用户数据导出、重试、撤销、限时下载和审计。
- 账号关闭支持删除内容、稳定匿名作者和依法保留三种结果。
- 大导出、失败、过期下载和重复匿名化保持幂等。

### `FUNC-P1-003` 附件误报放行完整状态机

现有独立放行权限、复核理由、确认、重新识别、审计和 UI 已经存在，不应重复开发。

剩余必须完成：

- 显式保存人工放行状态，而不是只把扫描状态改成普通 clean。
- 支持有权限撤销放行、撤销理由和不可变审计。
- 重新扫描与撤销之间具有明确并发和幂等规则。
- 撤销后旧签名下载或缓存不能绕过最新状态。

### `FUNC-P1-004` 商城库存、履约与财务风险

- 建立不可变库存流水和可售、预留、已售、退回、损坏、人工调整状态。
- 预留带到期时间；支付、取消、超时和退款幂等确认或释放。
- 提供负库存、异常预留、订单与库存不一致的恢复视图。
- 履约保存每次尝试、稳定幂等键、下次执行和外部结果摘要。
- 失败进入可查询队列，支持有理由、有确认和有审计的人工重放/取消。
- 建立争议、拒付、证据期限、负责人和风险处置状态机。
- 保存税费快照、发票、退款凭证和稳定编号。
- 提供按时间、渠道、币种、状态和税务维度生成的异步财务导出。

如果首发即开启真实资金商城，本项整体提升为 P0。

### `FUNC-P1-005` EE 空间发现、申请、邀请与离开

- 支持 private、request、public 策略和公开空间目录。
- 加入申请保存规则版本、留言、处理人、理由和时间。
- 支持申请、审批、拒绝、重新申请、离开和重新加入。
- 邀请具有到期、次数、绑定对象、预授角色、撤销和使用历史。
- 邀请明文只展示一次，接受时重新检查邀请人权限和角色层级。

### `FUNC-P1-006` EE 消息产品能力

- 消息附件选择、拖拽、粘贴、扫描、进度、取消、重试和权限安全下载。
- 消息反应的幂等添加/撤销、聚合和可靠实时同步。
- 消息置顶、取消置顶、置顶列表和规范深链。
- 服务端、权限安全的消息搜索及稳定分页。
- 离线提及、隐私安全摘要和多设备去重。
- 可信 online、idle、dnd、invisible 状态。
- 用户/空间聊天导出、保留、匿名化和 legal hold。

当前“搜索当前频道”只过滤客户端已经加载的消息窗口，不得作为
`EE-SEARCH-001` 已完成的证据。

### `FUNC-P1-007` EE 大空间与长历史

- 成员使用稳定游标分页，支持角色、状态和名称筛选。
- 100+ 频道、1000+ 成员和 10k 消息使用分页或虚拟列表。
- 加载更多保持选中项、草稿和滚动锚点。
- 频道未读/提及摘要使用批量查询，不逐频道请求。
- 搜索、分页、低速网络和补拉不会重挂载 `/app`。

### `FUNC-P1-008` 插件平台正式版能力

本项仅在产品对外宣传完整插件平台时作为正式版门禁。插件继续采用“安装即完全信任”的
信任模型，不新增不可信代码沙箱目标。

- 补齐 Commerce 写 API、通知、邮件、Webhook 和存储 Host API。
- 建立统一页面、导航、事件、翻译和 UI contribution registry。
- 完成多进程启停/升级 generation、确认和失败回滚协调。
- 增加安装后文件健康检查和明确的保留数据/清除数据卸载模式。
- 提供生成器、构建/验证 CLI、参考插件和兼容性矩阵。

## 7. P2：可选增强

以下能力不是第一版公众社区上线门禁，但不得显示空入口：

- EE 空间自定义表情。
- EE Webhook 与 Bot。

私信/群聊、语音、视频、Stage、收藏、投票和定时消息尚未完成独立产品设计，不进入当前
发布承诺，也不计入本轮缺失功能数量。

## 8. 功能发布门禁

版本只有同时满足以下功能条件，才能被标记为生产候选：

1. 所有适用 P0 均达到“已验证”。
2. 未完成的 P1/P2 使用服务端功能开关关闭，并隐藏所有普通用户和后台入口。
3. 权限、资金、附件、审核和实时关键路径有允许、拒绝、重放、并发和冲突测试。
4. Rails、JavaScript、TypeScript、I18N、迁移和生产前端构建全部通过。
5. 完成一次统一 Chrome 验收，而不是逐项开发时反复验收。
6. Chrome 覆盖桌面、390px 手机、中文、英文、空数据、错误、无权限、离线和重连。
7. CE 不存在 EE WebSocket/频道实现；EE 的最新提交历史包含最新 CE `main`。
8. 页面不包含开发要求、计划说明、无效导航或假“即将推出”功能。

自动化全部通过只代表当前代码没有发现回归，不代表未开发功能已经存在，也不能单独把
任务标记为“生产就绪”。

## 9. 推荐开发顺序

1. `FUNC-P0-001`：资金与权益高风险动作。
2. `FUNC-P0-002`：可靠事件、补拉与背压。
3. `FUNC-P0-003`：多人空间、频道、角色和管理台闭环。
4. `FUNC-P0-004`：屏蔽、禁言、通知和未读正确性。
5. `FUNC-P0-005`：权限解释、统一审计、审核与消息保留。
6. `FUNC-P0-006`：TOTP 恢复、邮箱与账号自助管理。
7. `FUNC-P0-007`：关键流程 I18N、可访问性与最终浏览器矩阵。
8. 根据首发范围选择共享商城 P1 或 EE 产品完整性 P1。

每个功能都必须按“数据状态 → 服务与权限 → API/任务/实时 → 审计 → 前端 →
自动化 → 统一 Chrome 验收”的顺序闭环。只有模型、按钮、路由或静态源码测试，不能视为
完成。
