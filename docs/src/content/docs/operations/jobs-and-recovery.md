在管理后台的“系统”中使用两个不同入口：

- “后台任务”（`/admin/system/jobs`）：查看运行模式、周期调度、队列快照、工作进程心跳、恢复投递记录和可执行的人工任务。
- “Sidekiq 控制台”（`/admin/system/sidekiq`）：在管理后台内查看队列、重试、计划任务、工作进程和 Sidekiq 运行详情。

它们都要求后台与系统模块访问权限，具体查看和写入权限分别控制：

| 操作 | 专用权限 |
| --- | --- |
| 查看后台任务页 | `system.jobs.read` |
| 提交人工任务 | `system.jobs.manage`，以及该任务要求的业务权限 |
| 查看 Sidekiq 控制台 | `system.sidekiq.read` |
| 在 Sidekiq 中重试、删除等写入操作 | `system.sidekiq.manage`，同时需要查看权限 |

有查看权限不代表可以管理任务。不要为了排查一个队列就授予全部系统权限。

## 嵌入式 Sidekiq 控制台

控制台默认在后台页面内加载，管理导航仍保留。打开具体队列、重试或任务页面时，浏览器地址会反映对应的控制台位置，可保存当前后台地址供有权限的同事继续查看。

如果提示控制台未能加载，可以选择“重试”，或使用“在新窗口中打开”。新窗口使用相同的账户和权限，不会绕过登录或写入限制。登录失效、两步验证尚未完成或权限被撤销时，应先重新完成登录与授权检查。

Sidekiq 中的重试可能再次执行业务副作用，删除队列项也不等于取消业务记录。对支付、发货、世界恢复等任务，优先使用相应业务页面提供的恢复流程；不要仅为清空失败计数而批量删除或重跑任务。

## 排查顺序

1. 在“后台任务”确认运行模式与 Cron 自动注册状态。开发模式会暂停周期任务自动注册；这不代表全部手动任务也被禁用。
2. 检查队列快照是否可用、工作进程心跳是否新鲜。快照不可用不能解释为队列为空。
3. 在 Sidekiq 查看对应队列和失败任务，核对任务类别、时间与重试状态，避免只看总数。
4. 对照[运行指标](/docs/operations/metrics-and-capacity/)检查请求错误、任务失败和队列积压是否同时异常。
5. 根据相关业务记录判断是否需要等待自动重试，还是使用已授权的人工恢复入口。

开发模式关闭后，后台工作进程需要按部署流程重启以恢复周期计划注册。如果生产环境意外处于开发模式，先确认配置来源和影响，再由运维修正；不要在 Sidekiq 中临时补建一套重复计划。

## 可恢复人工任务

“后台任务”只列出当前版本提供且你有权执行的任务。选择任务后按字段说明填写目标标识、范围和必要原因，核对后提交。

提交成功只表示已入队。继续检查人工任务运行记录及对应业务对象的最终状态；浏览器超时或页面关闭不代表任务停止，不要据此再次提交。任务目录没有提供的操作，应交给负责该功能的运维流程处理，不能通过输入任意任务类名执行。

反复失败时停止重试，保留任务标识、错误码和相关时间窗口，再转入故障处理。

Minecraft 托管世界的恢复和异常收敛有独立的计划、身份验证与确认步骤，见[世界备份与恢复](/docs/operations/minecraft-world-recovery/)。
