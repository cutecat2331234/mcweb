## 定位

工作人员工作台位于普通社区界面和站点管理后台之间，用于日常内容治理。它面向版主、审核员、附件安全人员等受限工作人员，不要求 `admin.access`，也不开放系统设置、身份组定义、站点所有权、密钥管理或基础设施健康检查。

网页入口是 `/app/staff`，审核队列是 `/app/staff/moderation-cases`。只有至少具备一种实际治理范围的用户才会看到入口并能够访问；普通用户不能进入工作人员页面查看案件。

## 开始处理事项

1. 从应用导航进入“站务工作台”，查看待处理、未领取、分配给本人和高风险事项。
2. 打开审核队列，按来源、状态、优先级、风险、板块、负责人或时间筛选。
3. 进入事项详情，先核对原始内容、可见证据、既有备注和同步警告，再领取或转派。
4. 选择当前允许的动作，阅读影响预览，按要求填写原因并确认。
5. 检查逐项结果和最新状态；批量操作出现部分失败时，只处理明确失败的事项，不要直接重复整个批次。

## 队列中的操作

- 统一处理待审核主题、待审核回复、帖子举报、垃圾命中、隔离附件和有权限查看的用户风险事项。
- 查看经过权限裁剪的证据；无证据权限时不返回原始内容。
- 领取、转派、取消转派和添加内部备注。
- 批量或单项执行批准、驳回、删除、移动、解决、驳回举报、警告、禁言等当前用户有权执行的操作。
- 高影响操作需要查看影响预览，并按提示完成确认；过期的授权不能继续使用。

举报复议和处置申诉还有独立队列，入口是 `/app/staff/report-appeals`。它不会把未提交的用户草稿当作待办；审核步骤和结果边界见[审核、案件与证据](/docs/staff/moderation-and-evidence/)。

## 权限边界

工作台不定义第二套角色。它复用全局身份组权限、板块版主关系和账号状态：

- 板块版主只能看到和处理其管理范围内的内容与举报。
- 附件证据、释放和删除分别受附件安全读取、释放、管理权限约束。
- 用户警告、禁言和封禁分别复用现有权限；封禁仍只允许站点所有者。
- 转派目标必须是活跃用户，并且对该事项拥有真实管理能力。
- 站点管理员保留身份组定义、所有权、全局安全策略、API 密钥和基础设施管理。

## 权限与一致性

- 工作台权限不等于管理后台权限；只能处理当前身份实际可见、可管理的事项。
- 外部工作人员工具必须使用绑定用户的细粒度 API scope，scope 不会扩大该用户本身的
  可见范围。接入方式见 [REST API](/docs/plugin-development/rest-api/)。
- 若事项已被他人领取或更新，旧页面会报告冲突。刷新详情后重新判断，不要覆盖较新的状态。
- 批量操作只显示全部选中事项共同允许的动作，并保留逐项结果。
- 权限不足时，证据正文、附件和用户安全资料会继续隐藏。
- 工作台、API 与管理后台操作会以不同来源写入审计记录。
