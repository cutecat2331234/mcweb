McWeb 的账户、论坛、商城、官网和管理后台有各自的页面入口，但仍使用同一站点的账户与权限。日常切换方法见[导航、搜索与求助](/docs/getting-started/navigation-and-help/)。

在“管理后台 → 系统 → 应用与扩展”（`/admin/system/applications`）查看内建应用、插件、包操作记录和运行诊断。这里的启用、停用或安装操作不是创建另一套独立站点。

## 内建应用与功能开关

论坛、商城、Minecraft 联动和官网博客入口随发行版提供。相应功能开关影响功能入口与可访问能力，不会卸载代码、删除数据库内容，或把一个应用升级为另一产品版本。

更改开关前，检查官网导航、已有书签、订单处理和外部集成是否仍引用该应用。使用当前设置页提供的开关并遵循校验提示；不要把“停用”当作数据清理。

论坛与商城至少需要保留一个启用；设置页会拒绝同时关闭两者。

内建应用不能在后台上传一个新版本来替换。更新它们需要按 McWeb 的发布流程更新站点。CE 不因此获得 EE 的实时频道或 EE-PVP 的测试、Tier 和赛季功能。

## 识别扩展类型

| 扩展 | 主要用途 | 管理时注意 |
| --- | --- | --- |
| 可信 Ruby 插件 | 在 McWeb 进程内扩展业务能力 | 与站点进程同权，必须先审查代码 |
| Minecraft Connector | 游戏服内的绑定、任务与事件联动 | 需要匹配的游戏服插件与站点配置 |
| mcweb-node | 托管游戏实例、备份和运行状态 | 节点授权不等于站点管理员权限 |
| 前台模板包 | 配色、样式和支持范围内的展示 | 不能替换业务应用或其权限逻辑 |
| Webhook | 向外部系统发送事件 | 保护签名密钥，核对目标地址与投递状态 |
| Minecraft 集成规则 | 按后台规则触发预置动作 | 只使用配置界面提供的条件和动作 |

## 安装可信 Ruby 插件

Ruby 插件不是隔离的低权限小组件。插件代码可以使用站点进程的数据库、文件、服务和环境权限；能力声明或包摘要不能证明代码安全。

插件可以随部署安装，也可以由具备 `system.plugins.manage` 权限的管理员上传已经审查的本地 ZIP 包。当前入口不提供远程插件目录、自动下载、自动升级、发布者签名验证或不可信代码沙箱。

操作前完成以下准备：

1. 从可信发布渠道取得完整包及预期 SHA-256，通过独立可信信息核对来源。
2. 审查插件代码、兼容版本、依赖、设置要求，以及安装、升级和卸载步骤是否会改变数据。
3. 备份相关数据与现有插件，安排必要的维护窗口和全部进程的重启或重载。
4. 在后台提交本地包及预期摘要，检查页面的预检结果，再执行安装或升级。
5. 完成后核对包操作记录、版本和诊断，确认所有 Web 与后台工作进程都加载了预期版本。

摘要匹配只说明文件与预期包一致，不代表发布者可信。不要安装来源不明的包，也不要把生产密钥或完整凭据附在诊断信息中。

更详细的包安装、升级与恢复操作见[插件市场运维](/docs/plugin-development/marketplace-operations/)。

## 启停、回滚与卸载

- 启用前确认依赖、兼容性和必要设置均满足要求。
- 停用后检查依赖该插件的功能、外部集成和后台任务；停用不是删除插件数据。
- 回滚或恢复前核对目标版本、包记录和数据库兼容性，不能仅凭文件可恢复就认定数据也可恢复。
- 卸载前阅读插件提供的卸载步骤，核对精确插件 ID、页面所示版本和确认内容。卸载可能执行插件的数据删除逻辑。

文件隔离或文件恢复机制不能撤销已经成功执行的数据删除。多进程部署的变更应与运维协调，不能只根据当前后台进程显示正常，就判断所有进程已经切换。

## 插件设置

在“系统 → 插件设置”管理已声明设置的插件。页面按插件提供的设置定义显示字段和校验结果；敏感项通常只显示“已配置”，不要据此判断它为空并覆盖。

设置与插件及其设置版本相关。升级、迁移或回滚时遵循页面提示，记录变更原因和原版本，不要直接修改数据库绕过校验。没有设置表单的插件不代表可以把任意站点配置作为它的设置写入。

## 诊断和目录对账

“应用与扩展”展示当前进程的加载状态、版本、依赖、能力声明及诊断。出现版本、文件或安装记录不一致时，先保留安全的错误码和操作编号，交给运维核对部署。

具备 `system.plugins.diagnostics` 权限时，可以使用“对账并补录”更新数据库中的插件清单。该动作不会修复包文件，也不会启用插件或改变当前运行状态；存在不一致时，仍需要处理对应原因。

需要自建扩展时再查阅[插件开发入门](/docs/plugin-development/getting-started/)、[SDK](/docs/plugin-development/sdk/)与[REST API](/docs/plugin-development/rest-api/)。
