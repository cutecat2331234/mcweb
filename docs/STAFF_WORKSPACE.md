# 工作人员工作台

## 定位

工作人员工作台位于普通社区界面和站点管理后台之间，用于日常内容治理。它面向版主、审核员、附件安全人员等受限工作人员，不要求 `admin.access`，也不开放系统设置、身份组定义、站点所有权、密钥管理或基础设施健康检查。

网页入口是 `/app/staff`，审核队列是 `/app/staff/moderation-cases`。只有至少具备一种实际治理范围的用户才会看到入口并能够访问；普通用户无法读取页面或 JSON 详情。

## 当前能力

- 汇总本人可见的待处理、未领取、分配给本人和高风险事项。
- 统一处理待审核主题、待审核回复、帖子举报、垃圾命中、隔离附件和有权限查看的用户风险事项。
- 按来源、状态、优先级、风险、板块、负责人和时间筛选。
- 查看经过权限裁剪的证据；无证据权限时不返回原始内容。
- 领取、转派、取消转派和添加内部备注。
- 批量或单项执行批准、驳回、删除、移动、解决、驳回举报、警告、禁言等当前用户有权执行的操作。
- 高影响操作先展示影响预览，再使用短期签名挑战和输入确认执行。
- 所有写入使用乐观锁、幂等请求和不可变审计记录；网页操作不会整页刷新。

## 权限边界

工作台不定义第二套角色。它复用全局身份组权限、板块版主关系和账号状态：

- 板块版主只能看到和处理其管理范围内的内容与举报。
- 附件证据、释放和删除分别受附件安全读取、释放、管理权限约束。
- 用户警告、禁言和封禁分别复用现有权限；封禁仍只允许站点所有者。
- 转派目标必须是活跃用户，并且对该事项拥有真实管理能力。
- 站点管理员保留身份组定义、所有权、全局安全策略、API 密钥和基础设施管理。

## 扩展契约

网页初始页面继续由 Rails + Inertia 渲染；筛选导航使用 Inertia 局部更新，详情、领取、转派和备注使用页面局部 JSON 请求。领域逻辑位于 `Community::ModerationWorkbench`，网页控制器与 `/api/v1/staff` 只是适配层。

外部应用使用细粒度 API scope，并且必须绑定用户。API scope 不能扩大绑定用户本身的可见范围。详情见 `docs/API.md`。

新的治理来源应接入统一的 `Community::ModerationCase` 投影，并提供以下信息：稳定来源类型和 ID、显示标题与摘要、风险和优先级、可选板块与目标用户、来源更新时间，以及由策略计算出的可用操作。来源同步必须可重复执行，不得创建重复事项。

新的治理操作应通过操作计划生成预览，使用签名状态快照防止授权后目标被替换，并在同一事务内执行领域写入、事项状态变更、操作记录和审计日志。外部事件只在事务成功后发布。

## 验收基线

- 无后台权限的板块版主能进入工作台，但不能进入 `/admin`。
- 普通用户、未绑定 API 密钥和无治理范围的绑定用户均被拒绝。
- 同一事项不会因并发领取、转派或备注覆盖更新；旧 `lock_version` 返回冲突。
- 批量操作只允许所有选中事项共同具备的操作，并保留逐项结果。
- 证据权限不足时不泄露正文、附件或用户安全资料。
- 网页端写操作只替换队列行或详情内容，不触发浏览器硬刷新。
- 工作人员网页、API 和管理后台产生可区分的审计来源。
