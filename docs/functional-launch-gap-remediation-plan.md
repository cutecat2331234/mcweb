# McWeb 公众产品功能上线缺口修复计划

> 状态：实施中（CE 共享功能及自动化门禁已完成，EE 频道产品化与统一 Chrome 验收进行中）
> 最近源码复核：2026-08-02
> 适用范围：McWeb CE 共享功能与 McWeb EE 专属公众 `/app`
> 目标：只从产品功能角度消除当前 NO-GO；不把部署、容量、监控、灾备或安全运维混入本计划

## 1. 当前结论与发布边界

当前核心官网、论坛、账号、商城以及 EE 实时聊天已经有真实纵向实现，但完整公众产品仍有
四组可复现缺口：EE 空间所有者无法自助完成角色和结构治理；共享论坛板块无法安全退役；
用户邮件没有完整遵循收件人语言；PDF 收据会把中文内容破坏成问号。

在这些任务完成前：

- CE 只能在明确关闭或限制问题入口后进行受控灰度，不能宣称完整双语功能就绪。
- EE 若要求站点管理员代管所有空间，可以受控预览；面向公众的自助付费社区仍为 NO-GO。
- 未纳入当前首发范围的私信群聊、语音、视频、Stage 和定时消息不得显示空入口，也不作为
  本轮上线阻断。

## 2. 版本与提交顺序

1. 所有共享模型、迁移、服务、后台、邮件、收据、I18N 和测试先进入 CE `main`。
2. EE 使用普通 Git merge 包含 CE 的完整提交历史，不复制补丁、不 squash、不 rebase。
3. 只有空间/频道实时产品的公众治理 UI、API 和测试进入 EE 专属提交。
4. 最终必须证明最新 CE 提交是 EE `main` 的祖先，并分别完成自动化与 Chrome 验收。

## 4. `SHARED-FORUM-001`：论坛板块安全生命周期

### 4.1 数据与服务

- 增加可恢复的归档状态，保留板块、主题、回复、附件、订阅和审核记录。
- 归档板块从常规发现和发帖入口移除，并禁止创建主题；既有内容的读取与回复规则必须明确，
  不能依靠前端隐藏按钮代替服务端约束。
- 恢复时重新进入正常排序和权限计算，不创建重复板块或丢失原有关系。
- 永久删除仅允许不存在主题、子板块及其他受保护依赖的空板块；服务返回稳定的影响预览和
  阻止原因，禁止使用模型默认级联作为管理功能。
- 所有归档、恢复和删除动作写入统一审计，记录操作者、原因、前后状态和请求关联信息。

### 4.2 后台体验

- 列表可区分正常与已归档板块，并支持状态筛选。
- 详情页使用紧凑操作区；影响预览和危险确认放入 Arco Modal/Drawer，不把页面纵向拉长。
- 危险动作使用独立权限、明确中文/英文说明、原因输入与二次确认；失败后保留输入。
- 桌面和窄屏均不得横向溢出，状态不能只靠颜色表达。

### 4.3 自动化

- 覆盖归档/恢复幂等、发帖约束、发现隐藏、权限拒绝、审计、并发和安全删除阻断。
- 覆盖后台 props、动作路由、I18N 键与无 JavaScript 降级响应。

## 5. `SHARED-I18N-001`：用户邮件语言闭环

- 统一从直接用户、订单用户、退款所属订单用户、主题通知用户等真实收件人解析 locale。
- 身份验证、密码重置、TOTP 恢复、论坛回复/提及/私信及订单全生命周期邮件的主题和正文
  全部进入 I18N；不得继续拼接硬编码中文。
- 异步任务必须显式携带或可稳定解析收件人语言，不能依赖发件进程的全局默认 locale。
- 中英翻译键保持对称；动态标题、用户名、订单号和金额通过参数插值，不进入翻译键名。
- 测试至少覆盖同一邮件在 `zh-CN` 与 `en` 下的主题、正文和链接，以及缺失 locale 的明确
  默认行为。

## 6. `SHARED-RECEIPT-001`：Unicode 双语 PDF 收据

- 收据语言跟随订单用户 locale，标题、字段、状态、金额、物流和优惠标签全部 I18N。
- 删除 ASCII 有损转换；中文商品名、规格、地址、备注、物流名称必须原样可读。
- 使用可嵌入的 Unicode 字体，并在生产镜像中确定安装或随应用提供；Windows 开发环境允许
  有序候选字体。缺少字体时返回可翻译的明确错误，不能悄悄生成乱码文件。
- 保持金额、币种、分页和长文本换行稳定，下载文件名与 Content-Type 正确。
- 测试解析生成 PDF，确认中英文文本存在、中文不变成 `?`，并覆盖缺字体和长订单。

## 7. `EE-GOV-001`：公众角色治理闭环

### 7.1 API 与权限

- 在空间作用域提供角色更新、删除、排序和成员取消分配接口。
- 复用现有 `Ee::Chat` 服务、权限目录、委派边界、最后所有者保护、幂等/乐观锁和审计，
  不复制 `/admin/chat` 的业务逻辑。
- 禁止删除受保护角色、越权授予权限、把角色排序到自身委派范围之外，或移除最后的可治理
  身份；失败返回稳定机器码和本地化用户文案。

### 7.2 `/app` 体验

- 角色列表展示成员数、权限摘要、受保护状态和可用操作。
- 创建、复制、编辑使用同一 Arco Modal；删除显示影响预览；成员分配使用可搜索 Drawer，
  同时支持取消分配。
- 排序采用明确的上移/下移或拖拽反馈，并在服务失败时恢复原顺序。
- 管理工具保持折叠在 Drawer/Modal 内，不展开成长页面；方形数据区与圆角交互表面混用，
  通过语义色和留白突出主次。

## 8. `EE-GOV-002`：公众类别与频道治理闭环

- 接通已经存在的类别更新/归档/恢复/删除、频道归档/恢复/删除和结构排序 API。
- 类别删除前展示频道和消息影响；非空结构优先归档，永久删除必须遵守服务端保护条件。
- 频道退役后清理或失效对应未读、草稿、深链和实时订阅；恢复后局部刷新结构，不整页重载。
- 结构排序必须持久化、处理版本冲突并通过可靠事件同步其他标签页。
- `/app` 使用 Arco Tree/List、Tag、Dropdown、Modal 和 Drawer 组织操作；移动端操作区不遮挡
  内容，所有中文/英文文案齐全，无开发要求说明或技术 key 暴露给普通用户。

## 9. EE 文字频道产品化

本轮目标不是机械复制 Discord 或 KOOK，也不以空入口冒充语音、视频或机器人平台；目标是
让现有 EE 文字社区能力达到普通公众社区可以长期使用的完整度。设计依据采用 Discord 官方的
[搜索](https://support.discord.com/hc/en-us/articles/115000468588-How-to-Use-Search-on-Discord)、
[置顶](https://support.discord.com/hc/en-us/articles/221421867-Pin-Messages-FAQ)、
[线程](https://support.discord.com/hc/en-us/articles/4403205878423-Threads-FAQ)与
[论坛频道](https://support.discord.com/hc/en-us/articles/6208479917079-Forum-Channels-FAQ)帮助文档，
以及 KOOK 官方的[用户/频道对象](https://developer.kookapp.cn/doc/objects)和
[频道消息能力](https://developer.kookapp.cn/doc/http/message)。这些资料只用于提炼信息层级、
能力可发现性和权限反馈，不复制其品牌视觉。

### 9.1 `EE-CHANNEL-001`：信息架构与可发现性

- 频道头部固定展示频道名、简介、在线/成员摘要和连接状态；搜索、置顶、未读、收藏、通知、
  成员列表放在可识别的 Arco Toolbar/Dropdown 中，桌面保留高频直达，窄屏收敛到频道详情
  Drawer，不能把重要功能藏在没有标签的图标海里。
- 左侧空间/频道树明确区分类别、频道、归档、未读、提及和当前项；状态不能只靠颜色，折叠、
  排序和切换保持局部状态，不整页刷新。
- 右侧上下文面板使用成员、线程和频道信息等明确标签；用户关闭后记忆选择，移动端改为 Drawer，
  不强行压缩消息正文。
- 新频道和空频道提供正常用户需要的名称、用途与首条消息引导，不出现开发要求、实现状态或
  “企业内部”文案。

### 9.2 `EE-CHANNEL-002`：消息与讨论闭环

- 每条消息在 hover、键盘聚焦和移动端长按/更多菜单中提供同一组受权限约束的动作：回复或
  打开线程、反应、保存、置顶、复制链接、编辑/删除自己的消息、举报；危险动作使用 Modal。
- 线程在侧栏/Drawer 中展示根消息、回复数、独立草稿、双向分页、定位与新消息状态；关闭线程
  返回原滚动位置，浏览器前进/后退保持 SPA 导航。
- 搜索支持关键字、作者、频道、日期/内容类型等当前后端真实支持的筛选，并能跳回上下文；
  置顶、收藏、通知和未读结果都提供“定位到消息”，无法访问时给出本地化原因。
- 附件展示上传/扫描/失败进度、预览与下载边界；反应显示计数及成员；编辑、删除、举报、
  置顶和反应通过实时事件局部收敛，不刷新整个页面。
- 输入区突出主操作，附件、Emoji、提及和其他工具分组；保留发送失败内容、慢速模式、超时、
  只读和权限拒绝的明确状态，禁止“点了没反应”。

### 9.3 `EE-CHANNEL-003`：成员资料与生产体验

- 点击消息或成员列表头像首次只打开 Arco Popover/Trigger 资料卡：较大头像、显示名、用户名、
  在线状态、简介、加入时间和真实身份组/角色；字段不存在时省略，不生成假资料。
- 同一头像在资料卡打开时再次点击，或点击卡片中明确的“查看个人主页”，才通过 Inertia/History
  SPA 导航到现有用户主页。点击外部、`Esc`、焦点离开和空间切换安全关闭；键盘可完整操作。
- 移动端用 Bottom Drawer/Modal 承载资料卡，避免悬浮层越界；资料卡和消息区混合使用圆角交互
  表面与较硬的数据分隔，不把所有内容堆成同色方框。
- 加载、空、离线、重连、游标过期、权限被撤销和成员离开均有稳定状态；重连使用已有可靠事件
  补偿，用户草稿和当前位置不丢失。
- 中英 I18N、用户文案扫描、TypeScript、组件测试、390px 横向溢出、焦点、ARIA、控制台错误和
  双标签实时都属于完成门禁。

### 9.4 明确不伪装完成的边界

- 语音、视频、直播、屏幕共享、Stage、完整 Bot/Webhook 市场和跨服务器联邦不是本轮文字频道
  上线阻断；未形成真实纵向实现前不显示入口。
- “接近 Discord/KOOK”在本轮指文字社区核心工作流、信息层级、反馈与可靠性达到可持续使用，
  不代表承诺其全部媒体、商业化或生态功能。

## 10. 统一验收门禁

### 10.1 自动化

- CE：相关 Ruby 集成/服务测试、JavaScript、TypeScript、I18N 键对称、RuboCop 和构建通过。
- CE 提交后合并到 EE，并证明 ancestry。
- EE：角色与结构治理服务/API/前端测试、完整 Ruby/JavaScript/TypeScript/I18N、RuboCop 和
  构建通过。

`2972 tests / 31834 assertions / 0 failures / 0 errors / 1 Windows 平台预期 skip`；JavaScript
`150/150`、TypeScript、前端 I18N `4469` 键、用户文案门禁、RuboCop `1842` 文件、Zeitwerk、
Vite 构建与 `git diff --check` 全部通过。唯一 skip 是只在 Linux 验证生产 Noto CJK 字体路径
与实际渲染的契约；Docker 与 CI 已安装并检查同一字体文件。

### 10.2 Chrome 一次性验收

- CE：中英用户触发身份、论坛和订单邮件预览；中文订单下载收据；板块归档/恢复/删除阻断。
- EE：普通空间所有者完成角色增删改排、成员分配/取消、类别与频道完整生命周期。
- EE：普通成员完成头像资料卡二段导航、搜索/置顶/收藏/未读定位、回复/线程、反应、附件、
  通知偏好和举报；无权动作不出现或返回明确原因。
- EE 双标签验证结构和权限变化局部实时收敛；操作不触发整页刷新。
- 桌面与 390px 移动端检查 Drawer/Modal、焦点、键盘、语义色、间距和横向溢出。
- 控制台无新增 error/warning，页面无原始 I18N key、开发说明或不可达入口。

## 11. 发布判定

只有 `SHARED-FORUM-001`、`SHARED-I18N-001`、`SHARED-RECEIPT-001`、`EE-GOV-001`、
`EE-GOV-002`、三个 `EE-CHANNEL-*` 和 `ACCEPT-FUNC-001` 全部有源码、测试和可见验收证据后，
才把“纯功能”结论从 NO-GO 更新为 GO。外部多实例、容量和灾备仍需单独生产门禁，不得由
本计划的功能完成状态代替。
