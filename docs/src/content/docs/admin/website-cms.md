在“管理后台 → 官网”维护对外网站的页面、文章、导航和主题。入口是否可见，以及能否编辑或发布，由你的后台访问范围和对应权限决定；有编辑权限不等于有发布权限。

## 页面和首页

1. 打开“页面”，新建页面或选择已有页面编辑。
2. 填写标题、路径标识、页面类型和 SEO 信息。路径标识会影响访问地址，修改前检查是否已有公开链接或导航引用。
3. 在“区块”中添加和调整内容，设置顺序及是否显示。
4. 保存后检查内容和各语言版本，再由有发布权限的人员发布或安排定时发布。

页面支持主视觉区块（`hero`）和富文本区块（`rich_text`）。主视觉区块用于标题、副标题和行动按钮；富文本区块用于正文。使用编辑页面提供的字段，不要在内容中插入脚本或未经审查的代码。

已发布且类型为首页（`home`）的页面用于网站根地址 `/`；没有可用 CMS 首页时，网站显示内置首页。启用 CMS 首页后，`/home` 会转向 `/`。

## 文章

在“文章”中维护新闻或博客内容，填写标题、摘要、正文、路径标识及 SEO 信息。正文支持 Markdown，公开地址采用 `/blog/文章路径标识`。

文章与页面一样区分草稿、发布及定时发布等状态。保存编辑不代表访客已经能看到；发布后从公开地址检查内容和链接。

## 导航和多语言内容

导航用于配置官网的可见链接和顺序。更改页面路径、归档或移入回收站前，先处理仍指向它的导航，避免留下失效入口。

页面、文章和区块可维护语言版本。切换编辑语言后检查标题、正文或区块文字，以及 SEO 标题和描述；发布前不要只检查默认语言。界面语言与内容翻译是不同的设置，切换界面不会自动翻译正文。

## 定时发布

为内容选择定时发布并填写时间后，由后台周期任务在到期后处理，通常不是到达该秒就立即上线。时间已过仍未发布时，先核对内容状态和安排时间，再查看[后台任务与调度](/docs/operations/jobs-and-recovery/)；不要连续重复提交发布。

## 修订与恢复

从页面或文章的“修订”入口查看历史记录。选择需要恢复的修订，核对内容差异、填写原因并完成页面要求的确认。

恢复修订会把当前这条内容改回所选历史内容，并设为草稿；它不会另建一篇自动上线的页面或文章。恢复后重新检查区块、翻译、主题、路径和导航，再决定是否发布。路径占用、首页冲突、主题缺失等问题可能阻止恢复。

“归档”“移入回收站”和“永久清理”用途不同。误删内容的处理与权限说明，见[内容回收、保留与清理](/docs/admin/content-recovery/)。

## 主题与前台模板

官网主题用于网站展示配置；“前台模板”入口用于上传、预览和启用模板包，两者不要混淆。模板包页面提供当前规范及起始包，操作时以它报告的支持范围、摘要和状态为准。

启用模板前检查桌面和移动页面、导航与表单。删除非内置模板包不等于删除内置回退模板。模板是展示扩展，不是安装论坛、商城或执行任意 Ruby 代码的入口。

## 常用权限

| 职责 | 权限 |
| --- | --- |
| 查看页面 | `website.pages.read` |
| 编辑页面 | `website.pages.edit` |
| 发布或安排页面发布 | `website.pages.publish` |
| 查看文章 | `website.articles.read` |
| 编辑文章 | `website.articles.edit` |
| 发布或安排文章发布 | `website.articles.publish` |
| 恢复回收站内容 | `website.content.restore`，并具备该内容的读取、编辑权限 |
| 永久清理回收站内容 | `website.content.purge`，并具备该内容的读取权限 |

不要通过给工作人员完整系统权限来解决单项 CMS 操作缺少授权的问题。
